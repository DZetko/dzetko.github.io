What is Casely

A local legal AI for Czech lawyers.
Purpose
Manage client case files, draft legal documents, and ground every answer in active Czech law
Law source
e-Sbírka — the official Czech open-data statute book, updated daily. Both current in-force law and historical versions (partitioned by decade back to the 1990s) are indexed, so the system can answer about repealed law too
Client data
Case files, contracts, and scanned documents are ingested per matter. Scans and photos are transcribed by a vision model (Tesseract 5). All data stays local
Inference
Runs fully local on a single GPU (RTX 4000 Blackwell, 4-bit quantization), or targets a remote inference endpoint for end-users who are not lawyers and only need on-demand access
App
Electron / React desktop app, FastAPI backend. Answers streaming using WebSocket

✎ Query & Intent Routing
Stage 1 — code filter
Czech verb stems and document-type nouns are matched in code. If nothing triggers, the turn is a question — no LLM call needed.
"Jaká je výpovědní doba?" → no trigger → answer
Stage 2 — LLM classification
Only runs when stage 1 triggers. Constrained JSON output: answer | draft | revise.
"Sepiš předžalobní výzvu pro pana Nováka." → sepiš triggers → LLM → draft
Two response modes
Single-shot pipeline (direct answer) or multi-hop research agent (up to 8 steps)
▩ Embedding BAAI/bge-m3
Dense vector
1024 dimensions — captures meaning, not exact words. "nájemné" and "nájem bytu" land close together even though the words differ
Sparse vector
Lexical weights over a 250k-token vocabulary, pruned to top 1000 non-zero entries. Catches exact terms dense misses: "§ 2205", "č. 89/2012 Sb."
XLM-RoBERTa backbone
A multilingual transformer pre-trained on 100 languages including Czech. BGE-M3 is built on top of it — this is why it handles Czech diacritics and morphology well out of the box
Chunking
Target 1000 tokens, max 1200, overlap 100. Each chunk carries a contextual header with the § path and statute title
Why BGE-M3
Only model that produces dense + sparse in a single pass, so both retrieval channels share one embedding call
⌖ Hybrid Search pgvector
Dense KNN
Top 20 candidates (TOP_K_DENSE=20)
Sparse KNN
Top 20 candidates (TOP_K_SPARSE=20) — catches exact legal terms that dense misses
Temporal filter
valid_from ≤ date AND valid_to ≥ date — only returns the currently in-force version of each statute
∖ Reciprocal Rank Fusion
Formula
score += 1/(k + rank) per channel, RRF_K=60
Input
Union of two rankings — up to 40 unique candidates (dense ∪ sparse)
Why RRF
Parameter-free fusion — no weight training needed. Dense captures semantics, sparse captures exact terms. RRF is robust to outlier scores
◆ BGE-M3 Reranking BAAI/bge-reranker-v2-m3
Input
~40 RRF-fused candidates, each (query, passage) pair scored by the reranker
Output
Top-ranked passages passed to the LLM for generation
⚙ Generator & Agent Qwen 3.6 27B (IQ4_XS)
Single-shot
Top passages + query → LLM answer with [n] citations. Refuses to answer when evidence is insufficient
Agent (multi-hop)
Up to 8 steps. Tools: search_law, search_client_docs, extract, resolve_matter
Guardrails
[DOPLNIT: …] markers for missing facts, citations must resolve to real passages
Inference
RTX 4000 Blackwell, llama-server, 4-bit quantization. Fallback: remote inference endpoint
☑ Output

Legal analysis in Czech with numbered citations [1], [2]… Each resolves to a specific statute § or client document chunk
Draft
Legal document (demand letter, contract, notice…).

LLM Choice

Language and factual errors across all 6 generations per model.
Gemma 4 12B (Q4_K_M)
Google, 12B parameters, instruction-tuned. Q4_K_M quantization (4-bit, medium quality — groups weights with per-group scaling factors).
14
errors — invented words, wrong gender, wrong numbers, corrupted forms
Qwen 3.6 27B (IQ4_XS)
Alibaba Qwen team, 27B parameters, instruction-tuned with multi-token prediction. IQ4_XS quantization (importance-matrix 4-bit — allocates bits based on weight significance, more compact).
0
errors — grammatically correct, professional Czech
Apertus 70B
70B parameters — too large to host locally on a single RTX 4000 Blackwell (24 GB VRAM). Available via Public AI as a remote inference endpoint for end-users who need on-demand access without dedicated hardware.
